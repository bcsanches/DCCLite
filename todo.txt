	- User activates right signal on Block1:
		- Signal knows its blocks and side on block
		- System grabs block 1 info
		- request right side connection
			- Interlock is returned, so asks interlock
				- incoming from B1, get valid path
					- there are two options on path table, so the turnout states must be checked
					- based on turnout states, finds the valid path, suppose P2
					- may return null if no valid path (turnouts not on correct route)
				- when path is found, asks if it is free (section must be inactive)
				- if path is free, grab next block
				
			- B3 is returned
			- If B3 if free, check right signal, if exists, reserve all this route, clear signal and stops
				- If B3 does not contain a signal, continue on next block / interlock until it is blocked, chain finishes or a signal is found

	- SignalController
		- controls a single signal
		- starts at danger state
		- It references a Section that it protects
		- when requested, can be cleared, it checks:
			- section is clear?
			- section route, if any, is set?

			- if it can be cleared, set the Signal aspect
			- mark the section as reserved and expected direction, follow section links until it finds a signal on the same direction

		- When not in danger state, as soon as its sections gets ocupied, resets to DANGER
